# Delegation plan

The rule used to decide who does what: **the higher the cost of an error and
the harder it is to spot, the less autonomy the AI gets.**

## Inside the product

| Component | Done by | Why |
|---|---|---|
| Price download and validation | Deterministic code | Errors are detectable by rules (missing interval, wrong resolution) |
| Charge/discharge schedule | Deterministic optimiser (MILP) | Exact, reproducible, free; an LLM would be slower, costlier and wrong in subtle ways |
| "Worth cycling?" verdict | Deterministic code | A one-line formula the analyst can redo by hand |
| Ranking of scenarios | Deterministic code | The main acceptance test must be checkable by a machine |
| Explaining the schedule, answering questions (phase 2) | LLM agent, bounded | Interpretation in natural language is what LLMs are good at; every number must come from a tool call |
| The dispatch decision | The analyst | Never delegated |

## While building it

| Activity | Mode | Why |
|---|---|---|
| Framing and market research | Augmentation | AI gathers sources, domain expertise decides |
| Data ingestion code | Automation | AI writes, tests and validation rules catch errors |
| Optimiser formulation | Augmentation | The equations are written and checked by hand; a wrong constraint is silent and costly |
| Charts and dashboard | Augmentation | AI proposes, the visual standard is set by the author |
| Agent in production | Bounded autonomy | Few tools, numbers only from tools, no decisions |
| Tests and evaluations | Augmentation | Expected answers written by the author, variants generated by AI |
